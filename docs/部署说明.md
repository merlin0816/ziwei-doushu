# 部署说明（本站增补版）

> 本仓库是 [Renhuai123/ziwei-doushu](https://github.com/Renhuai123/ziwei-doushu)（MIT）的**下游增强版**。
> 在上游开源的排盘引擎与 Demo 界面之上，增补了三项能力：**原版解读本地查表**、**AI 讲解（多轮追问）**、**起盘记录**。
> 断语库、账号体系、商业站前端仍**不在**开源范围内，本仓库也没有包含它们。

---

## 0. 三个增补功能是什么

| 功能 | 说明 | 是否联网 |
|---|---|---|
| **原版解读 · 本地数据** | 直接查作者开源的**解读数据集 v4.0**（674,976 张命盘 × 13 维），返回该盘 13 个维度的原文，不经过 AI、不烧模型额度、同一输入恒得同一输出 | 首次查某一年会从 GitHub Release 下载该年数据（约 2 MB），之后走本地缓存 |
| **AI 讲解 · DeepSeek** | 把命盘压成结构化简报（十二宫/四化/大限/空宫借星/健康取象）后交给任意 OpenAI 兼容模型，**每个主题一条独立对话，可连续追问** | 需要模型服务 |
| **起盘记录** | 起过的盘存在浏览器 localStorage，可一键重开、单条删除、清空；解读与对话一并缓存，重看秒开、能接着追问 | 不联网 |

## 1. 前置条件

| 需要 | 说明 |
|---|---|
| Docker 20+ 与 Docker Compose v2 | 用「方式一 / 二」时需要；仅本地开发可跳过 |
| 一个 OpenAI 兼容的模型服务 | **只有「AI 讲解」需要**；不配也能用排盘和「原版解读」。可以是 DeepSeek、Moonshot、one-api/CodeBuddy 之类的网关，或任何兼容 `/v1/chat/completions` 的服务 |
| 4 GB 内存、1 GB 磁盘 | 镜像约 960 MB（含 Node 运行时）；数据缓存每年约 2 MB |

> ⚠️ **模型网关的一个已知坑**：有些 CodeBuddy 类网关（例如 workbuddy2api）会**静默丢弃 `role: "system"` 的消息**。本项目已经绕开这一点——盘面简报与指令都并入第一条 `user` 消息。如果你自己改代码，注意别把上下文放回 system 角色。

## 2. 方式一：docker compose（推荐）

```bash
git clone <你的 fork 地址>
cd ziwei-doushu

# 1) 配置模型（只填 key 也能跑，base_url/model 有默认值）
cp .env.example .env
vi .env          # 填入 LLM_API_KEY

# 2) 数据集缓存目录（容器内 /data，宿主挂到 ./data）
mkdir -p data

# 3) 起
docker compose up -d --build

# 4) 打开
#    排盘 + 解读： http://<主机IP>:8899/chart
#    独立 AI 页： http://<主机IP>:8899/interpret
```

看日志与状态：

```bash
docker compose logs -f --tail 50
docker compose ps
```

---

## 3. 方式二：Portainer Stack

1. Portainer → **Stacks → Add stack** → 名字随意（如 `ziwei-doushu`）
2. Build method 选 **Web editor**，把 `docker-compose.yml` 全文粘进去
3. 下方的 **Environment variables** 里加一条：`LLM_API_KEY` = 你的 key
   （**不要**把 key 写进 compose 文件本身；`docker-compose.yml` 里用的是 `${LLM_API_KEY:-}`）
4. **Deploy the stack**；以后升级点 **Update the stack**

数据缓存在宿主 `./data`（Portainer 部署时请把 `volumes` 改成绝对路径，例如 `/opt/ziwei-doushu/data:/data`）。

## 5. 环境变量

| 变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `LLM_API_KEY` | 仅 AI 讲解需要 | — | 模型服务的 key。不配时 `/api/interpret` 返回 503 并给出明确提示，其余功能照常 |
| `LLM_BASE_URL` | 否 | `http://127.0.0.1:7863/v1` | OpenAI 兼容 API 根地址（**换网关时才需要**） |
| `LLM_MODEL` | 否 | `deepseek-v4-flash` | 模型 id（换模型时才需要） |
| `LLM_TIMEOUT_MS` | 否 | `180000` | 单次请求超时 |
| `ZIWEI_DATA_DIR` | 否 | `/data/cache` | 数据集缓存目录（容器内） |

> 设计取舍：`base_url` / `model` / `timeout` 都**有代码默认值**，不设也能跑。只有**密钥**必须外部化。

## 6. 解读数据集缓存

「原版解读」读的是作者发布的 **v4.0 数据集**（`Renhuai123/ziwei-doushu` 的 Release `v4.0-13d`，CC BY 4.0）。

- 按年份分文件：`year-1950.jsonl.zst` … `year-2026.jsonl.zst`，每个约 **2 MB**（解压后约 0.7 GB）
- 首次查某一年时，服务端自动下载该年文件到 `ZIWEI_DATA_DIR`（默认 `/data/cache`），之后复用
- 解压用镜像内的 `zstd -d -c --long=27` 流式读取，找到目标记录就立即终止，**不读完整年**（首次约 15 s，之后约 2 s）
- **本仓库不重分发数据集**，只在运行时按需下载。若要离线部署，手动把 `year-YYYY.jsonl.zst` 放进缓存目录即可

## 7. 升级与回滚

```bash
git pull && docker compose up -d --build      # 升级
git checkout <上一个 tag/commit> && docker compose up -d --build   # 回滚
```

浏览器侧数据（起盘记录、解读缓存）存在 localStorage，升级不影响；但**换浏览器/清缓存会丢**（这是设计取舍，未做服务端存储）。

## 8. 故障排查

| 现象 | 原因与处理 |
|---|---|
| 页面能开，点 AI 讲解报「本站未配置 LLM」 | `LLM_API_KEY` 没注入。检查 `docker compose config` 或 Portainer 的 Environment variables，改完需要重启容器 |
| 报「模型接口返回 401/403」 | key 与 base_url 不配套；换网关时要同时改这两个 |
| 报「模型返回为空」 | 某些推理模型只输出 `reasoning_content`；本项目已兜底取它。若仍为空，换一个模型（`LLM_MODEL`） |
| 「原版解读」一直转圈或 502 | 容器不能出网（下载数据集失败）。确认容器可访问 `github.com`；离线环境改用第 6 节的离线放置办法 |
| 查表返回 404 | 该「日期+时辰+性别」不在数据集里（数据只覆盖 1950–2026 的真实日期）；检查是不是真太阳时把时辰算到了边界另一侧 |
| 排盘结果和别的排盘软件差一个时辰 | 本项目按**真太阳时**校正（出生地经度 + 均时差）；不填出生地则不做校正。数据集本身**未做**校正，所以两边口径要对齐 |
| 记录/对话不见了 | localStorage 被清（换浏览器、无痕模式、清站点数据）。属预期 |
| 构建时报 `Cannot find module '@/components/AiPanel'` | 你把增补文件放错路径了，见 `APPLY.md` |
